# Бета-платформа: профили, права и комнаты

Старая игра `culture-quest-z.onrender.com` и её база не изменяются. Новые комнаты создаются только на домене бета-платформы и имеют собственные состояния, чаты, таймеры, вопросы, криптографические ключи и имена cookie.

## Запуск локально

Требуется Node.js 22.13 или новее. Из корня репозитория:

```sh
npm ci
npm ci --prefix beta-lobby
```

Создайте локальный файл `.env.platform` (он не должен попадать в Git) с `LOBBY_SESSION_SECRET`, `LOBBY_OWNER_CODE`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` и `LOBBY_PUBLIC_ORIGIN=http://localhost:3000`. Секрет сессии и начальный код владельца должны быть разными случайными строками длиной не менее 32 символов. Генерация каждой строки:

```sh
node -e "process.stdout.write(require('node:crypto').randomBytes(48).toString('base64url'))"
```

В Google OAuth-клиенте добавьте точный callback `http://localhost:3000/auth/google/callback`. Запуск:

```sh
node --env-file=.env.platform beta-lobby/portal-server.mjs
```

Без `LOBBY_DATABASE_URL` локальная разработка сохраняет файлы в `beta-lobby/data/platform/`. Можно задать `LOBBY_PLATFORM_DIRECTORY`. Хранилище в памяти используется только тестами.

## Render: отдельное постоянное хранилище

Сервис: `culture-quest-accounts-beta`. Точка запуска остаётся `node beta-lobby/portal-server.mjs`. Команда сборки остаётся прежней:

```sh
npm ci --omit=dev && npm ci --prefix beta-lobby --omit=dev && node beta-lobby/build.mjs
```

Добавьте **отдельную** PostgreSQL в `LOBBY_DATABASE_URL`. Не копируйте туда `DATABASE_URL` старой игры. Для Render PostgreSQL в том же workspace и регионе используйте Internal URL; для внешнего провайдера — его строку с требуемым TLS. Приложение создаёт одну таблицу `cq_platform_documents` в новой базе. Нужны права создания таблицы и чтения/записи.

Добавьте `LOBBY_OWNER_CODE`: отдельную случайную строку для первой активации владельца. Сервер не возвращает этот код через API и не пишет в журнал. После первого владельца повторная активация этим кодом запрещена; переменную можно удалить после успешной активации.

На Render **без `LOBBY_DATABASE_URL` профили/комнаты отключены** (`GET /api/platform/status` → `available:false`). Существующие Google-вход и переходы к старой игре продолжают работать. Эфемерная файловая система Render не выдаётся за постоянную базу.

В workspace уже занята единственная бесплатная PostgreSQL. Автоматически платная база не создаётся. Нужна отдельная внешняя PostgreSQL либо согласованная платная Render PostgreSQL.

## Первый запуск владельца

1. Войти через Google в лобби.
2. Открыть «Приглашение преподавателя», ввести начальный `LOBBY_OWNER_CODE`.
3. Появится «Управление доступом». Создать одноразовое приглашение преподавателя: срок 24 часа, один аккаунт. В базе хранится SHA-256 приглашения.
4. Преподаватель входит собственным Google-аккаунтом и активирует приглашение. Сам Google-вход не даёт полномочий.
5. Владелец может выдавать/отзывать права уже зарегистрированным аккаунтам. Владелец не может отозвать свою роль через этот интерфейс.

Права новой платформы не являются персональными кодами администраторов старой игры и не меняют их.

## Комнаты и результаты

- Преподаватель создаёт комнату, задаёт название, предмет и режим team/solo. По умолчанию разрешены до четырёх одновременно открытых комнат на один процесс; это защитный предел для бета-версии, а не подтверждённая нагрузочная ёмкость бесплатного тарифа.
- Пульт комнаты открывается владельцу комнаты и владельцу платформы по Google-сессии. Чужой Google-аккаунт и гость таких прав не получают. Отзыв роли проверяется при последующих действиях пульта.
- В пульте нужно добавить свои вопросы и открыть регистрацию. Публичные демонстрационные вопросы выключены по умолчанию.
- Постоянная ссылка комнаты имеет вид `/rooms/<uuid>/student.html`. Гости входят без Google; их результаты не становятся личной Google-историей. Удалённые/закрытые комнаты не пускают новых игроков.
- Подтверждённый Google-аккаунт связывается с реальным серверным playerId после регистрации или восстановления его действующей сессии. Клиент не может прислать произвольный результат или связать чужой playerId. Один аккаунт не занимает два активных места в одной комнате.
- После окончания матча сохраняются очки, место, правильные/все ответы и полученные достижения. Итоги команды используют тот же рейтинг `очки + экономика × 5`, что и игровой движок. Участник без записанного участия в вопросах не получает чужой завершённый матч.
- Повторное сохранение и перезапуск не дублируют матч. Возвращение результата в аккаунт требует подключения базы; старая рабочая игра автоматически не импортируется.
- Закрытие комнаты завершает её подключения, оставляет сохранённое состояние и историю. Нельзя закрыть чужую комнату обычными правами преподавателя.

## Надёжность и ограничения

Используется один Node-процесс с отдельным движком на каждую активную комнату. HTTP и WebSocket маршрутизируются только в локальные игровые процессы по серверным UUID. Ключи комнат не публикуются. Приложение не создаёт отдельный платный Render service для каждой комнаты.

PostgreSQL-транзакции блокируют документ платформы при изменении ролей, приглашений и истории. Сессионная advisory-блокировка не даёт двум инстансам одновременно вести одну комнату при деплое. Потеря блокировки запрещает дальнейшее сохранение старого экземпляра. Локальные файлы предназначены для одного процесса.

Локально проверены OAuth-регрессии, выдача/отзыв прав, сохранение на диск, изоляция двух HTTP/WebSocket-комнат и отсутствие доступа к чужому пульту. Живая PostgreSQL и физические телефоны в этой проверке не участвовали. До массовой лекции нужна проверка нескольких реальных устройств и отдельной PostgreSQL.

Платформа пока не включает войны, торговые нововведения, генерацию вопросов через платный ИИ, перенос старых результатов или визуальные стадии города на 5000/10000 очков.


## Отдельный кабинет создателей

`/creators.html` доступен только Google-аккаунтам с серверной ролью `owner` (Адилет) или `creator` (Ернур). Назначения хранятся в PostgreSQL. Страница и API проверяют роль на сервере. Адилет приглашает Ернура отдельным одноразовым кодом; место второго создателя единственное. Обычное приглашение преподавателя не даёт роль создателя.

В кабинете: все комнаты, полный игровой пульт каждой комнаты, список аккаунтов, выдача/отзыв преподавательских прав, приостановка обычных аккаунтов, просмотр команд и участников, перенос/переименование/исключение игроков, корректировка ресурсов и экономики, вопросы с правильными ответами и JSON-редактором версии вопроса, управление таймером и перезапуск комнаты. Обновление вопроса не подменяет уже опубликованный активный вопрос. Опасные действия требуют подтверждения.

Адилет и Ернур защищены от блокировки, понижения и исключения друг другом. Внутри новой комнаты подтверждённый Google-аккаунт получает соответствующий игровой creatorId и существующий инструмент создателя без ввода персонального кода. Места создателей проверяются отдельно от обычной вместимости. Управление работает только с комнатами бета-платформы; старый сервер и его персональные сессии остаются отдельными.

## Расширенный кабинет: игры, статистика и код

Во вкладке «Конструктор игр» сохраняются самостоятельные варианты на готовом движке: культурная стратегия, личная викторина и блиц. Настраиваются название, предмет, командный/личный режим, способ командного ответа, число команд и мест, длительность, автопереход, перки, торговля, цвета и вопросы. Шаблон можно копировать. Это конструктор вариантов существующего движка, а не универсальный редактор произвольных жанров.

Создание комнаты доступно прямо из кабинета. Ответ содержит одноразовый `CQR-…` код управления со сроком 24 часа. Преподаватель входит через Google в лобби и вводит код в «Код преподавателя или комнаты». Аккаунт получает управление только назначенной комнатой, без автоматической глобальной роли преподавателя. Создатели могут перевыпустить код и отозвать приглашённое управление. Закрытую комнату можно открыть снова с тем же UUID/URL, если есть место в лимите открытых комнат.

Усыпление освобождает движок, подключения и PostgreSQL advisory-lock, но не удаляет комнату, вопросы или результаты. Следующий вход поднимает её заново. Автоматическая проверка раз в минуту усыпляет движки после 30 минут без пользовательских действий; сетевые ping/pong не считаются действиями. Закрытие, в отличие от усыпления, запрещает новые подключения до повторного открытия. Перезагрузка движка сохраняет данные и заставляет браузеры переподключиться.

В аккаунтах редактируются сыгранные игры, победы, правильные и все ответы. Корректировка сохраняется отдельно от настоящей истории матчей, с причиной и версией счётчиков. Реальный новый матч добавляется к скорректированным значениям. Нельзя установить отрицательные/дробные числа, больше побед чем игр или больше правильных ответов чем всех ответов. Устаревшая форма отклоняется. Статистику Адилета меняет только Адилет; преподаватели статистику не меняют. Технический журнал корректировок закрыт для обычных игроков.

В комнате доступны настройки состава, правила, регистрация и Live State JSON. Сервер проверяет revision, состав участников и вопросы; JSON не позволяет исключить защищённых создателей или менять платформенные роли и ключи. Во время активного вопроса применяются ограничения игрового движка.

### Живые расширения

Вкладка «Код и расширения» хранит CSS и браузерный JavaScript-модуль внутри сохранённой игры. CSS меняют создатели; JavaScript — только Адилет. При сохранении JavaScript проходит синтаксическую проверку Node.js без выполнения кода. До пяти предыдущих версий можно восстановить. Код и стили ограничены 32 КБ каждый, тело запроса — 128 КБ.

Связанные открытые комнаты получают событие `extension:update`; CSS обновляется, а модуль загружается по новому номеру версии. Рекомендуемый контракт:

```js
export default function ({engine, mode, onState}) {
  const off = onState(state => {
    // Здесь доступно только состояние, выданное сервером этому пользователю.
  });
  return () => off();
}
```

Возвращайте функцию очистки для обработчиков и созданных DOM-элементов. Необработанная ошибка расширения не останавливает основной движок; произвольные побочные эффекты стороннего JS могут потребовать обновления страницы. Расширения исполняются в браузере, не на Node.js сервере. Они не получают серверные секреты и не обходят серверную проверку прав. Не помещайте ключи в эти файлы: код доступен участникам соответствующей комнаты.

Исходники перечисленных файлов движка доступны создателям для просмотра. `.env`, конфигурационные секреты, произвольные пути и файлы вне списка не выдаются. Изменение серверного Node.js-кода остаётся операцией Git/деплоя: кабинет не исполняет присланные серверные скрипты в общем процессе.

## Создание комнат и визуальная конфигурация

Начиная с этой версии комнаты создают только серверные роли `owner` и `creator` (Адилет и Ернур). Глобальная роль преподавателя, приглашение на управление комнатой и любые клиентские поля/флаги не дают права создавать новую комнату. Ограничение проверяется в домене и обоих HTTP-сценариях создания. Уже выданное управление существующими комнатами сохраняется.

В конструкторе появился редактор двух поверхностей: «Преподаватель» и «Участник». Он работает с адаптивной сеткой из 12 колонок: порядок блоков меняется перетаскиванием либо кнопками вверх/вниз, ширина — ⅓, ½, ⅔ или вся строка. На небольших экранах блоки складываются в одну колонку. Для дополнительных блоков можно задать видимость и начальное сворачивание. Вопрос участника, его команда и базовые элементы пульта не удаляются. Предпросмотр показывает схему интерфейса, а не запущенную WebGL-карту.

Настраиваются две палитры (тёмная/светлая), акценты, размер текста, отступы, скругления и высота карты. Мобильная карта ограничена 230px. Цвета и размеры проходят серверную проверку; произвольный CSS в поля цветов или структуры не принимается. Пользовательские CSS-расширения остаются отдельным инструментом для Адилета/Ернура.

Функции задаются независимо от положения блоков: карта, чат, музыка, достижения/перки, рейтинг, торговля, силлабус, редактор вопросов, изменение команд и игроков, экономика, изменение формата, организация, резервные копии, журнал, технический JSON/расширения, сигналы. Стартовый набор — простой урок с картой, рейтингом и управлением участниками. Можно выбрать «Только квиз» или «Все функции», затем настроить вручную.

Выключение функции скрывает её элементы и блокирует соответствующие действия обычных преподавателей и игроков на сервере, включая HTTP bulk-запросы. Создатели сохраняют свой отдельный управляющий кабинет. При выключенной карте Three.js не загружается; отключённые достижения не выдаются и не запускают новые общие анимации. Смена схемы не требует перезапуска открытой комнаты. Включение достижений, торговли и сигналов после выключения восстанавливает их стартовые флаги; дальше действуют обычные игровые ограничения.

Проверенные `features`/`design` входят в сохраняемый шаблон. При создании или явном применении шаблона они копируются в конфигурацию комнаты, поэтому последующее редактирование шаблона не переставляет интерфейс уже идущей пары самопроизвольно. Открытую комнату можно изменить прямо в кабинете: «Управлять» → «Функции и визуальная структура комнаты» → «Применить к комнате». Новое состояние с конфигурацией получают её подключённые браузеры.

Основной одиночный сервер не изменён и старые комнаты без конфигурации продолжают использовать прежний интерфейс. Модуль `room-layout.js` в корне — единый источник схемы/рендеринга; build копирует его в публичную папку лобби для редактора. Эта копия не редактируется отдельно.
