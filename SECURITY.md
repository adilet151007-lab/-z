# Безопасность учебной сессии

Обновление от 23 октября 2026 года. Это описание реализованных ограничений и проверок, не сертификат безопасности.

| Риск | Реализованная защита |
| --- | --- |
| Флаг роли, имя или URL изменены через F12 | Сервер выводит роль из своей сессии и проверяет каждую команду; клиентские флаги не принимаются |
| Токен скопирован из localStorage | Браузер использует HttpOnly/SameSite/Secure cookie; миграция заменяет старый токен и убирает его из локального хранилища |
| Запрос отправлен чужому сокету | HTTP-запрос связан с сокетом, его отдельным доказательством сессии, cookie и допустимым Origin |
| Делегат получил слишком широкие права | Известные разрешения принимаются только как boolean; доступ к вопросам, составу, игре и эффектам разделён; сброс с исключением требует прав на игру и игроков |
| Одноразовый код использован двумя людьми | Случайный код хранится как хеш; погашение, имя, место и выдача прав сохраняются одной серверной транзакцией |
| Ошибка PostgreSQL при входе/правке | Изменение откатывается и не рассылается; приглашение не расходуется |
| Перегрузка крупными сообщениями | WebSocket до 256 КБ, обычные события до 16 КБ, до 8 ожидающих команд сокета, общая очередь до 256; крупные импорты отдельно и после проверки доступа |
| Подмена сайта или внедрение скрипта | SameSite cookie, Origin/CSRF-проверки, CSP с nonce, запрет iframe, ограничение источников, экранирование пользовательского текста |
| Повтор старого входа преподавателя после выхода | Отзыв подписанного токена хранится на сервере; смена пароля также меняет проверяемую версию |

Неиспользованные приглашения действуют час, разрешения могут истекать по времени или отзываться. Ни приглашение, ни JSON-патч не дают возможности выдавать новые права, менять персональные ключи другого владельца или исполнять JS на сервере. Полномочия двух персональных владельцев сохраняются; их защищённые сессии не удаляются делегатами или через массовое исключение.

Известные или опубликованные персональные коды необходимо заменить в своей панели. Новый код показывается один раз в результате операции; в базе остаётся хеш. Эти ключи не входят в экспорт редактора и архив игры. Резервирование PostgreSQL и секретов инфраструктуры остаётся отдельной задачей владельца.

Публичность HTML/JS и репозитория не считается защитной границей. Авторизованный пользователь может прочитать данные, которые разрешено отправлять именно ему. HttpOnly уменьшает возможность чтения cookie из JS, но не делает XSS безвредным. Проверки приложения не заменяют защиту хостинга от распределённых атак, настройку сети, контроль доступа к GitHub/Render и регулярное обновление зависимостей.

Локальные проверки: `npm run test:full`, включая `tests/security-expansion.test.js`. Нагрузочные сценарии не гарантируют работу сотен физических телефонов на любом Wi-Fi или бесплатном сервере. Тесты выполняются на изолированном состоянии, не на данных занятия.

Опорные рекомендации: https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html, https://socket.io/docs/v4/middlewares/, https://expressjs.com/en/advanced/best-practice-security/.
