# Мәдениеттану — Великий путь, версия 2

Рабочая игра для одной аудитории: от 1 до 50 команд по четыре человека, отдельные
страницы студента и преподавателя, общий сервер Node.js + Socket.IO и карта Three.js.
Студенты могут подключаться с разных устройств и из разных сетей через интернет.

## Быстрый запуск на Render — вручную

Вам нужны один репозиторий GitHub, одна база PostgreSQL и один Web Service на Render.
Обе страницы и сервер работают по одному домену. GitHub Pages включать не нужно.

### 1. Загрузите файлы на GitHub

1. Распакуйте архив. Откройте папку с `package.json` и `server.js`.
2. Создайте репозиторий GitHub. Можно выбрать Private, чтобы банк вопросов
   и ответы не были видны в публичном репозитории.
3. Нажмите **Add file → Upload files**. Загрузите содержимое папки проекта,
   а не сам ZIP. `package.json`, `package-lock.json`, `server.js` и `render.yaml`
   должны оказаться в корне репозитория.
4. Сохраните изменения кнопкой **Commit changes**.
5. Не загружайте `.env`, `node_modules` и папку `data`.

### 2. Создайте PostgreSQL

1. Откройте https://dashboard.render.com/ и войдите через GitHub.
2. Выберите **New → Postgres**.
3. Имя: например, `culture-quest-db`.
4. Регион: **Frankfurt**. Для сервера ниже выберите тот же регион.
5. Выберите **Free**, если этот вариант доступен в вашем аккаунте.
6. Создайте базу и дождитесь готовности.
7. В меню **Connect** скопируйте **Internal Database URL**.
   Это секрет: вставляйте его только в настройки сервера Render.

Бесплатная база Render действует 30 дней с момента создания. Для длительного
использования потребуется продлить хранение на платном тарифе или подключить
другой PostgreSQL через `DATABASE_URL`. Не удаляйте базу перед повторным
развёртыванием сервера: именно в ней находятся результаты и вопросы.

### 3. Создайте сервер

1. Выберите **New → Web Service**, затем подключите созданный репозиторий GitHub.
2. Задайте настройки:

| Поле | Значение |
| --- | --- |
| Name | Например, `culture-quest` |
| Language / Runtime | Node |
| Branch | Ветка с загруженными файлами, обычно `main` |
| Region | Тот же регион, что у PostgreSQL, например Frankfurt |
| Root Directory | Оставьте пустым, если `package.json` в корне |
| Build Command | `npm ci --omit=dev` |
| Start Command | `npm start` |
| Instance Type | Free, если доступен |
| Health Check Path | `/health` |

Если `package.json` находится внутри `culture-quest/`, укажите
`culture-quest` в Root Directory вместо пустого значения.

3. В **Environment Variables** добавьте:

| Key | Value |
| --- | --- |
| `TEACHER_PASSWORD` | Ваш новый пароль преподавателя, от 8 до 256 символов |
| `SESSION_SECRET` | Случайная строка от 32 символов; можно воспользоваться Generate |
| `DATABASE_URL` | Полный Internal Database URL из шага 2 |
| `NODE_ENV` | `production` |

`PORT` задаёт Render автоматически. Сервер уже слушает `0.0.0.0` и читает этот
порт. `STATE_FILE` на бесплатном Render задавать не нужно: используйте PostgreSQL.
Сохраняйте `SESSION_SECRET` неизменным при повторных деплоях, чтобы вход
преподавателя продолжал действовать. Новый пароль автоматически отменяет
ранее выданные сессии преподавателя.

4. Нажмите **Deploy Web Service**. Дождитесь статуса **Live**.
5. Render выдаст адрес вида `https://имя-сервиса.onrender.com`.

### 4. Откройте две страницы

К полученному адресу сервиса добавьте:

| Для кого | Окончание адреса |
| --- | --- |
| Студенты | `/student.html` |
| Преподаватель | `/teacher.html` |

На странице преподавателя введите значение `TEACHER_PASSWORD`, которое вы
задали в Render. Студентам достаточно имени и выбора свободной команды.
Никакой адрес WebSocket вручную прописывать не нужно: страницы подключаются
к своему серверу автоматически. Учётная запись Render студентам не требуется.

До занятия откройте обе ссылки на двух устройствах, зарегистрируйте студента,
запустите вопрос и проверьте появление голоса на общей сессии. После проверки
нажмите «Сбросить игру» в панели преподавателя.

## Альтернатива — Render Blueprint

В архиве есть `render.yaml`, который описывает сервер и PostgreSQL вместе.
После загрузки файлов на GitHub можно выбрать **New → Blueprint**, подключить
репозиторий, указать `TEACHER_PASSWORD` и проверить список создаваемых ресурсов.
Render создаст `SESSION_SECRET` и свяжет `DATABASE_URL` с базой автоматически.
Создавайте ресурсы либо этим способом, либо вручную; одновременно оба варианта
не нужны. Если бесплатная база в аккаунте уже существует, используйте ручной
способ и подключите её.

## Локальный запуск на Windows / macOS / Linux

Установите Node.js 22 или новее. В терминале откройте папку проекта и выполните:

```bash
npm ci
npm run setup
npm start
```

`setup` один раз создаст локальный `.env` и покажет сгенерированный пароль
преподавателя. При повторном вызове существующие настройки не перезаписываются.

- Студенты: http://localhost:3000/student.html
- Преподаватель: http://localhost:3000/teacher.html

Для входа с телефонов в той же локальной сети замените `localhost` на локальный
IPv4-адрес компьютера, показанный командой `ipconfig` в Windows. Разрешите
Node.js входящие подключения в частной сети в брандмауэре. Изоляция клиентов
в университетском Wi-Fi может мешать такому подключению.

Без `DATABASE_URL` игра локально сохраняется атомарно в
`data/game-state.json`. Это серверный файл, браузер его скачать не может.
Перезапуск программы восстанавливает игру. Повреждённое сохранение вызывает
понятную ошибку запуска и не заменяется пустой игрой.

## Что исправлено

- Правами управляет сервер. Панель преподавателя требует пароль; сессия
  подписана серверным секретом и действует 24 часа. Все команды изменения
  очков, удаления игроков, редактора состояния и сброса проверяют права.
- Каждый участник получает случайный токен. Сервер связывает голос с этим
  участником, а не доверяет переданным клиентом имени, PID или команде.
- Повторный голос за тот же вариант ничего не прибавляет. Смена варианта
  переносит единственный голос участника на новый ответ.
- Пауза останавливает серверный таймер. Продолжение сохраняет оставшееся время.
  У преподавателя есть отдельная кнопка сброса таймера.
- По таймеру или кнопке итогов автоматически учитываются голоса большинства,
  даже если команда не нажала «Отправить». При равенстве голосов ручная
  отправка запрещена; если команда не договорилась до конца времени,
  применяется штраф. Пустые команды не штрафуются.
- Ограничение 4/4 проверяется в общей последовательной очереди сервера;
  одновременные запросы не занимают одно место несколько раз.
- Сохранение завершается до подтверждения команды и рассылки. При ошибке
  записи изменение отменяется. PostgreSQL хранит участников, вопросы,
  ресурсы, экономику и активный раунд при рестарте приложения.
- Студенты не получают будущие вопросы и правильный ответ до итогов.
  Серверные файлы и конфигурация не раздаются как статические файлы.
- Имя и текст вопроса экранируются перед выводом в HTML.
- Переподключение и обновление той же вкладки восстанавливают участника
  без повторного занятия места. Чужой или удалённый токен прав не даёт.
- Офлайн-участники видны преподавателю; их место можно освободить кнопкой ×.
  Место не удаляется при кратковременном обрыве связи. Закрытие вкладки может
  удалить её сессионный токен — такой слот преподаватель освобождает вручную.
- JSON-патч проверяет структуру и ревизию, чтобы случайно не затереть уже
  пришедшие голоса. Он редактирует ресурсы, экономику, состав команд и вопросы.
  Произвольный JavaScript на сервере не исполняется.
- 3D-сцена и прежняя цветовая схема сохранены. Изменения островов плавно
  анимируются между сообщениями сервера. Three.js и Socket.IO загружаются
  с самого сервера; внешние CDN для JavaScript не нужны.

## Управление и результаты

1. Зарегистрируйте команды.
2. Войдите преподавателем, выберите вопрос и длительность.
3. Запустите раунд. Участники обсуждают вопрос, голосуют и могут изменить выбор.
4. Ответ команды может отправить любой её участник. После отправки голосование
   этой команды закрывается. По таймеру неотправленный ответ определяется сам.
5. После итогов нажмите «Следующий вопрос» — список предложит следующий вопрос.
6. «Выгрузить ведомость» сохраняет CSV с именами, баллами и экономикой.
7. «Инструменты разработчика» открывает JSON-редактор с правами преподавателя.
   Кнопка «Скачать JSON» архивирует вопросы и показатели без секретных токенов.
   Для применения правок сначала загрузите свежий JSON кнопкой обновления.

Сброс игры очищает участников, баллы и раунд, но сохраняет названия команд, их регионы и банк вопросов.
Функции входа создателей по специальным ключам в этой версии не добавлялись.

## Особенности бесплатного Render

Сервис засыпает после 15 минут без входящего трафика. Первый запрос после
простоя может загружаться около минуты — откройте игру заранее. PostgreSQL
сохраняет игру независимо от файловой системы Web Service. Время активного
неприостановленного раунда продолжает идти во время перезапуска сервера;
просроченный раунд будет подсчитан после запуска. Для длинного перерыва ставьте
игру на паузу. Приложение рассчитано на один экземпляр сервера, как на Free.

## Проверки

```bash
npm ci
npm test
```

Включены проверки правил, таймера, лимитов, привязки голосов к соединениям,
авторизации всех административных команд, скрытия ответов, реальных обменов
Socket.IO, восстановления из файла и SQL-адаптера PostgreSQL через pg-mem.
pg-mem проверяет SQL-логику; соединение с конкретной базой Render проверяется
при реальном развёртывании.

## Если запуск не удался

| Сообщение или симптом | Что проверить |
| --- | --- |
| Не найден `package.json` | Root Directory; в GitHub должны быть распакованные файлы |
| `Задайте TEACHER_PASSWORD` | Добавьте переменную Render, пароль минимум 8 символов |
| `Задайте SESSION_SECRET` | Добавьте строку минимум 32 символа |
| Нет подключения к PostgreSQL | DATABASE_URL, готовность базы, одинаковый регион |
| База стала недоступна через месяц | Истёк срок бесплатного PostgreSQL |
| Пароль не принимается | Это значение TEACHER_PASSWORD, а не пароль от Render |
| Сервер запускается, но `/` показывает 404 | Проверьте, что загружена именно эта версия server.js |
| Свободные места заняты отключёнными игроками | Удалите их кнопкой × в панели преподавателя |
| Патч конфликтует с ревизией | Обновите JSON и повторите правку актуальных данных |

Официальные инструкции: https://render.com/docs/deploy-node-express-app,
https://render.com/docs/databases, https://render.com/docs/free.


## Развитие города и карта

Ресурс каждой команды ограничен 1000 на сервере. Правильный ответ и ручное начисление доводят ресурс максимум до 1000; JSON-патч с большим числом отклоняется. Старые сохранения с ресурсом выше 1000 автоматически ограничиваются при загрузке без удаления игроков и вопросов. На 1000 регион получает завершённый город; дальнейшие правильные ответы засчитываются с прибавкой 0. Другие команды продолжают играть. Преподаватель может уменьшить ресурс для корректировки или сбросить игру.

| Ресурс | Этап | Жилые здания |
|---|---|---|
| 0–99 | Территория | 0 |
| 100–249 | Поселение | 4 |
| 250–499 | Ауыл | 12 |
| 500–749 | Малый город | 24 |
| 750–999 | Большой город | 42 |
| 1000 | Город построен | 64 + завершённая городская панорама |

К домам поэтапно добавляются дороги, площадь, культурный памятник и многоэтажные кварталы. Стадии одинаковы в панели и 3D-сцене. Экономика управляет высотой, освещением и кризисным туманом отдельно от строительства.

Карта построена на реальных географических контурах Казахстана и областей. Для Сарыарқа объединены Карагандинская область и Ұлытау: это игровое приближение историко-культурной территории, не утверждение её точных исторических границ. Остальные три игровых региона используют контуры областей Жетісу, Маңғыстау и Түркістан. Высоты, растительность и постройки — авторская стилизация, а не цифровая модель высот или точная реконструкция существующих городов.

Источник контуров: SimpleMaps / Pareto Software, [Kazakhstan GIS](https://simplemaps.com/gis/country/kz), [Creative Commons Attribution 4.0](https://creativecommons.org/licenses/by/4.0/). Изменения: упрощение контуров, объединение двух областей, проекция координат в 3D. Данные включены в `region-geography.js` и не требуют внешнего картографического API при запуске.

Нажатие на регион приближает камеру. «Вся карта» возвращает общий вид. Здания объединены по материалам для сокращения числа вызовов отрисовки. При отключённом WebGL квиз остаётся доступен.


## Большая аудитория: команды и участники

- В панели преподавателя «Команды аудитории» можно создать недостающие команды одним действием. Для 150 студентов выберите 38: это 152 места. Максимум — 50 команд, 200 мест.
- Каждая команда имеет собственные имя, ресурс 0–1000, экономику и до четырёх участников. Можно создавать отдельные команды, переименовывать, менять привязку к региону и удалять их.
- Удаление команды освобождает все её места, удаляет голоса и ответ команды в текущем раунде. Остальные команды не меняются. Последнюю команду удалить нельзя.
- Кнопка × у участника исключает его и освобождает место. Она не является постоянной блокировкой человека: участник может зарегистрироваться снова.
- Вход студентов содержит поиск по названию команды или региону, когда команд больше восьми. Пароли студентам не нужны.
- Четыре географических региона остаются картой мира. Общая карта показывает среднее развитие непустых команд региона; преподаватель может выбрать конкретную команду в «Город команды». Студент всегда видит развитие своей команды в её регионе.
- Сервер объединяет частые рассылки состояния с интервалом 40 мс. В интеграционном тесте проверены 150 независимых подключений, регистрация, голосование и начисление очков. Это локальная проверка протокола с хранилищем в памяти, не гарантия производительности бесплатного тарифа Render при любой нагрузке.

## Банк вопросов и предварительные ответы

Преподаватель может искать, создавать, редактировать и удалять вопросы. Редактор позволяет менять четыре варианта, правильный ответ, баллы, тему и пояснение. Версия вопроса защищает от перезаписи изменений другого преподавателя.

Активный раунд использует сохранённый снимок вопроса. Изменения в банке действуют со следующего запуска и не меняют задним числом текущие голоса и правильный ответ. Во время активного раунда удалить его вопрос нельзя.

«Ответы преподавателя» показывает правильный вариант до подведения итогов, предварительный ответ каждой команды, наличие равенства голосов, число голосовавших и факт отправки ответа. Пока ответ не отправлен, большинство может измениться. Ресурсы и экономические штрафы применяются только при подведении итогов.

До завершения раунда студентам не передаются правильный ответ, пояснение, исходный фрагмент документа и предварительная правильность команд. Все операции редактирования и генерации требуют серверной авторизации преподавателя.

Кнопка «Скрыть ответы для проектора» скрывает закрытый обзор, банк вопросов, силлабус и административные формы на экране преподавателя. Это режим отображения в авторизованной панели, а не отдельная публичная ссылка.

## Силлабус → темы → черновики вопросов

В панели преподавателя загрузите PDF, DOCX или TXT либо вставьте текст. Размер — до 10 МБ, PDF — до 100 страниц, извлечённый текст — до 120 000 символов. Старые файлы DOC нужно сохранить как DOCX. PDF должен содержать текстовый слой; распознавания сканов (OCR) нет.

Документ разбирается в браузере: PDF.js извлекает текст PDF, Mammoth — текст DOCX. На сервер отправляется извлечённый текст, а не исходный файл. Исходный документ и полный текст не сохраняются в базе; сохраняются только добавленные преподавателем вопросы и их короткие исходные фрагменты.

1. «Найти темы» выделяет русские, казахские и английские заголовки. Отметьте нужные темы и при необходимости добавьте свои.
2. Выберите 1–60 черновиков и нажмите «Подготовить вопросы».
3. Для явных определений вида «Термин — определение» создаются задания с пропущенным термином. Остальные вопросы подбираются из встроенного учебного банка культурологии по найденным темам. Источник каждого вопроса показан явно. Это бесплатная обработка и подбор без LLM/API.
4. Правильные варианты перемешиваются. Каждый черновик можно отредактировать, поменять правильный ответ или исключить из импорта.
5. «Добавить выбранные в банк» сохраняет вопросы для всех преподавателей. Точные дубликаты формулировок пропускаются. После добавления вопросы доступны в обычном редакторе.

Если в силлабусе только расписание, а подходящих тем или определений нет, система сообщает о нехватке материала. Недостающие вопросы и факты не придумываются. Для новых предметов добавьте учебный текст или вопросы вручную. Автоматический подбор нужно проверить на соответствие содержанию вашего курса.

Новые серверные файлы `syllabus-engine.js` и `syllabus-bank.js` не раздаются браузерам. `syllabus-ui.js` — отдельный модуль интерфейса преподавателя. Сохранения схемы 2 автоматически читаются схемой 3 с сохранением четырёх прежних команд, участников и банка.
