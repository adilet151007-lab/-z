# Инструкция владельцу «Мәдениеттану 3D»

Редакция: 23 октября 2026 года. Один сервер обслуживает две разные страницы; переключателя «студент / преподаватель» в игре нет.

## 1. Что передать новому владельцу

- Репозиторий приложения с package-lock.json и этим руководством.
- Собственный аккаунт хостинга и собственную базу данных; не передавайте чужой production DATABASE_URL.
- Секреты передаются отдельно через менеджер паролей, не в GitHub и не в чате.
- Права на название, логотип и учебные материалы. Результат предварительной проверки — LICENSE_AUDIT.md и /licenses.html.
- До работы с реальными именами: сведения об операторе, контакт, срок хранения и решение о допустимом регионе размещения данных. Для Казахстана нужна отдельная правовая проверка локализации баз и трансграничной передачи. Зарубежный Render сам по себе не обеспечивает соответствие.

## 2. Локальный запуск

Установите Node.js 22.13+ и Git. Из корня полученного репозитория:

```sh
npm ci
npm run setup
npm start
```

`setup` создаёт `.env`, только если его ещё нет, и показывает сгенерированный пароль преподавателя. Существующий `.env` не заменяется.

- Участник: http://localhost:3000/student.html
- Преподаватель: http://localhost:3000/teacher.html
- Состояние сервера: http://localhost:3000/health
- Политика: http://localhost:3000/privacy.html
- Лицензии: http://localhost:3000/licenses.html

Другие устройства не могут использовать `localhost` вашего компьютера. Для телефонов используйте опубликованный HTTPS-адрес или защищённый сервер в сети аудитории. GitHub Pages не запускает Node.js/WebSocket-сервер.

## 3. Запуск на Render

Это инструкция технического размещения, а не заключение о соответствии обработке персональных данных. Создайте **Web Service**, подключите собственный репозиторий и существующий PostgreSQL того же региона:

| Поле | Значение |
| --- | --- |
| Runtime | Node |
| Build Command | `npm ci --omit=dev` |
| Start Command | `npm start` |
| Health Check Path | `/health` |

Переменные Environment:

| Переменная | Назначение |
| --- | --- |
| `TEACHER_PASSWORD` | Новый пароль преподавателя, 8–256 символов |
| `SESSION_SECRET` | Уникальный случайный секрет от 32 символов |
| `DATABASE_URL` | Внутренний URL своей базы PostgreSQL |
| `CREATOR_ERNUR_CODE`, `CREATOR_ADILET_CODE` | Необязательные персональные доступы; только по явному согласованию с владельцем |

Порт приходит через `PORT`; сервер слушает `0.0.0.0`. На Render без DATABASE_URL или явно настроенного постоянного STATE_FILE приложение не стартует, чтобы не создать иллюзию сохранности на временном диске.

Если auto-deploy включён, push запускает сборку сам. Иначе выберите Manual Deploy → Deploy latest commit. Дождитесь статуса **Live**, затем проверьте `/health`: `ok: true`, `storage: postgres`, `chatStorage: postgres`. Успех старого `/health` во время сборки не доказывает, что новая версия уже опубликована.

Пример двух ссылок после публикации:

```text
https://ВАШ-СЕРВИС.onrender.com/student.html
https://ВАШ-СЕРВИС.onrender.com/teacher.html
```

Участникам выдавайте только первую. Административные секреты не помещайте в URL.

Официальная инструкция: https://render.com/docs/deploy-node-express-app

## 4. Первичная настройка

Войдите преподавателем. Ниже основных панелей раскройте **Организация и предметы**:

1. Укажите университет, название платформы и цвета.
2. При необходимости загрузите разрешённый логотип PNG/JPEG/WebP до 150 КБ. Внешние ссылки и SVG не принимаются.
3. Введите предметы по одному в строке и выберите текущий.
4. Укажите полное название оператора данных (включая обязательные реквизиты, если применимо) и публичный контакт для запросов.
5. Сохраните. Изменения появятся на подключённых страницах без перезагрузки.

Вопросы привязаны к предмету. Старые вопросы без поля `subject` относятся к «Мәдениеттану». Новый предмет имеет пустой банк, пока вы не добавите свои вопросы или не импортируете силлабус. Смена предмета не обнуляет рейтинг и не создаёт независимую комнату: для нового занятия отдельно сохраните ведомость и сбросьте игру. Это одна общая учебная сессия, не многопользовательская SaaS-система с изолированными кабинетами преподавателей.

## 5. Проведение пары

1. Откройте **Формат пары** под списком участников. Solo — индивидуальная игра. Для командного режима раскройте **Настройки команд**, задайте количество и вместимость: например, 30 × 5 = 150 мест. Доступно до 50 команд, до 50 мест в одной; общий защитный предел — 500 вошедших участников. При расширении сначала добавляются области, затем города внутри них. Города можно создавать вручную в редакторе команды.
2. Подготовьте банк текущего предмета. Проверяйте факты и права на материалы. Импорт PDF/DOCX/TXT извлекает определения и предлагает черновики, а не гарантированно правильные вопросы от внешнего ИИ.
3. Раздайте студенческую ссылку. Новый игрок подтверждает политику отдельной галочкой. Уже существующая сессия восстанавливается без выдуманного согласия задним числом.
4. Выберите способ ответа команды. В обычном режиме каждый выбирает вариант с семисекундным подтверждением. В режиме лидера лидер предлагает вариант, команда голосует за согласие/отказ, затем лидер вручную отправляет ответ после согласия большинства. Лидера можно назначить в карточке игрока. По таймеру неотправленный ответ лидера считается пропуском. Пауза останавливает таймер.
5. Для показа используйте **Режим проектора**: он скрывает правильные ответы и служебные формы. Не транслируйте приватную панель до включения этого режима.
6. После занятия откройте **Управление → Выгрузить ведомость**. Рейтинг и CSV отсортированы одинаково. При необходимости создайте копию перед сбросом.

Карта по умолчанию экономнее на телефонах. Кнопка **Экономно / Детально** управляет разрешением и тенями; карта может быть свёрнута. Вопросы работают даже при недоступности WebGL.

Городская команда использует территорию своей области на карте; это игровая визуализация, не отдельная точная кадастровая граница города. Кнопка «♫ Музыка» запускает негромкий синтезируемый фон после нажатия; громкость сохраняется, при скрытии страницы звук приостанавливается. Компактная подпись авторов постоянно открывает их карточку.

При желании включите обмен ресурсами: лидеры договариваются об обмене культурных очков на экономику между вопросами. Обмен нельзя принять повторно или использовать для превышения пределов. Военных механик в этой версии нет.

### Восстановление и награда за камбэк

При экономике ниже 100% два правильных ответа возвращают до 20% экономики. За оба этих ответа ресурсы не начисляются; обычные +25 возвращаются со следующего ответа после достижения 100%. Ошибка снимает 20% (минимум 15%) и не стирает накопленный первый верный ответ. Например: 80% → верно (1/2, ещё 80%) → верно (100%) → верно (+25 ресурсов). С 15% до 100% потребуется десять верных ответов.

Подведите итоги последнего нужного вопроса и нажмите **Завершить матч** в пульте. Команда, которая в этом матче упала до 15%, восстановилась до 100% ответами и заняла первое место, получает **«Ты смог, братец»**. Равное первое место учитывает всех лидеров. Банк вопросов не завершает матч автоматически: при необходимости продолжайте или повторяйте вопросы до итогового решения преподавателя.

У студентов есть сворачиваемая витрина **Достижения**. Награда сохраняется после F5; из карточки можно повторно посмотреть анимацию. В пульте преподавателя и в панели владельца **Live Control & Identity → Достижения** есть предпросмотр без выдачи и вручение выбранной команде или участнику, включая себя. Предпросмотр видит только проверяющий. Ручное вручение отмечено как специальное; оно не меняет экономику или ресурс. Дубликат за один матч не создаётся. Сброс игры очищает витрину.

Анимация бура и трещины в небе длится 6,4 секунды, не блокирует ответы и пропускается кнопкой или Escape. При включённом уменьшении движения в системе показывается спокойная карточка. Административные операции скрыты из игрового журнала; диагностические данные в закрытом состоянии сохраняются.

## 6. Резервные копии игры

Раскройте **Резервные копии и восстановление**:

- **Создать и скачать копию** сохраняет точку на сервере и скачивает зашифрованный JSON.
- Три последние точки хранятся в той же базе. Перед сбросом игры, массовым исключением и JSON-патчем автоматически сохраняется состояние.
- Серверные точки помогают отменить ошибку, но не защищают от потери всей базы. Регулярно скачивайте копии на отдельный носитель.
- Для скачанного файла нужен тот же `SESSION_SECRET`. Храните его отдельно от архива. Пароль преподавателя менять можно; изменение SESSION_SECRET делает старые зашифрованные архивы недоступными без прежнего ключа.
- Копия включает команды, участников и токены их игровых сессий, баллы, вопросы, оформление и раунд. В файле они зашифрованы AES-256-GCM. Чат и внешние файлы/ведомости в архив игры не входят.

Восстановление:

1. Сообщите аудитории и остановите игру.
2. Выберите серверную точку либо свой ранее скачанный файл.
3. Подтвердите замену. Сервер проверяет файл и текущую ревизию; повреждённая копия не должна менять игру.
4. Перед заменой создаётся ещё одна точка. Активный вопрос восстанавливается **на паузе**, а не с истёкшим старым временем.
5. Действующие персональные администраторы сохраняют свои сессии; старые привилегии из архива не воскрешаются. Делегированные доступы отзываются, при необходимости выдайте их заново.
6. Проверьте состав и возобновите раунд. Обычный игрок со старым сохранённым токеном восстановит место из копии.

Для резервирования **всей PostgreSQL**, включая чат, применяйте отдельный `pg_dump` или возможности провайдера. Встроенные функции восстановления Render зависят от тарифа; не предполагайте, что бесплатная база имеет PITR. Официально: https://render.com/docs/postgresql-backups. Восстанавливайте дамп сначала в новую пустую базу и проверяйте результат; не запускайте команды с удалением таблиц в рабочей базе без отдельного решения владельца.

## 7. Согласия, удаление данных и передача клиенту

- Не заполняйте галочку за студента. До начала занятия объясните, кто увидит имена и ответы, и определите альтернативу для отказавшихся.
- Приложение фиксирует версию и момент нового согласия; это техническая запись, а не универсальная гарантия законности обработки.
- Выход из команды не очищает журналы, старые сообщения, архивы и скачанные CSV. Назначьте ответственного, срок хранения и процедуру удаления из всех хранилищ; учитывайте это при восстановлении копии.
- Не включайте персональные коды создателей в продаваемую установку без явного разрешения владельца. Скрытый жест не является защитой: полномочия проверяет сервер.
- В персональной панели откройте **Приглашения и защита входа → Сгенерировать новый код**. Новый случайный код показывается только вам; сохраните его в менеджере паролей. Старый код отключается. Для нового клиента не переносите старые персональные ключи.
- Главный администратор создаёт одноразовые приглашения с выбранными разрешениями. Код действует час до активации, срок самих прав настраивается отдельно; 0 означает до сброса/отзыва. Получатель вводит код в поле имени и указывает имя и команду. Количество делегатов ограничено общим размером сессии, а не двумя персональными местами.
- После обновления старые токены автоматически переносятся из localStorage в защищённые cookie. Не очищайте данные браузера перед первым входом после обновления: это удалит прежний способ восстановления места. Cookie преподавателя хранится до 24 часов, игрока — до 30 дней, но сервер прекращает доступ раньше: после 30 минут без действий. Это касается студентов, делегатов, обоих владельцев и преподавателя. Выход преподавателя также отзывает его токен на сервере.
- Нажатия, ввод и прокрутка активной страницы продлевают срок. Фоновые обновления, музыка, открытый проектор и переподключения не считаются действиями. Закрытая страница освобождает место по окончании срока; после этого нужно войти заново. Преподаватель, показывающий только карту, тоже должен взаимодействовать со страницей хотя бы раз за 30 минут. Перезапуск Render не начинает отсчёт заново. При первом внедрении правила старые сессии получают 30 минут с момента обновления.
- Старые открытые вкладки получают обновление интерфейса. На переход предусмотрено 24 часа совместимости прежнего протокола; после переноса старый токен отзывается. Обычному студенту передаются только его состав, необходимые показатели, а в Solo — первые десять мест и его собственное настоящее место.
- Секреты, `.env`, `data/`, дампы и архивы не публикуются в Git.
- Используйте HTTPS и резервирование; регулярно проверяйте восстановление на тестовой установке.

## 8. Проверка и типовые проблемы

`npm test` запускает десять быстрых проверок. `npm run test:full` — весь регрессионный набор, включая права, восстановления, чаты и нагрузочный сценарий. Это не гарантия работы 150 телефонов на любом тарифе и Wi-Fi.

- **Нет связи:** дождитесь пробуждения сервера; клиент переподключается раз в две секунды. Не создавайте второго игрока.
- **Имя уже в команде после F5:** это восстановленная сессия. Вход сохраняется в браузере до 30 минут бездействия; очистка данных сайта удаляет токен, а оставшееся место автоматически освободится после истечения срока.
- **Нельзя запустить предмет:** добавьте вопросы именно текущего предмета.
- **Импорт архива отклонён:** проверьте оригинал файла и соответствие SESSION_SECRET. Не пытайтесь вручную править зашифрованный JSON.
- **Логотип не принят:** используйте небольшой PNG/JPEG/WebP с правом использования.
- **Карта недоступна:** включите WebGL либо сверните карту. Квиз остаётся рабочим.
